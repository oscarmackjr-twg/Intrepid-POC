**Per D-12, D-13, D-14, D-15, D-16, D-17, D-18:**

**Step 1 — Add `pytest-cov` to requirements.txt (per D-16):**
Add `pytest-cov>=4.0` (or pin to a specific version after checking `pip index versions pytest-cov`) to `backend/requirements.txt`. Place it after the existing `pytest-asyncio==0.24.0` line. Do NOT add `--cov` flags to `backend/pytest.ini` addopts (per D-18 — coverage is CI-only).

**Step 2 — Add `unit-tests` job to `.github/workflows/deploy-test.yml` (per D-12, D-14, D-15):**
Add a new job named `unit-tests` at the same level as `security-quality-gate`. It runs in PARALLEL with `security-quality-gate` (not after it). The job structure:

```yaml
  unit-tests:
    runs-on: ubuntu-latest
    permissions:
      contents: read

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: pip install -r backend/requirements.txt

      - name: Run unit tests with coverage
        working-directory: backend
        run: pytest -m "not integration" --tb=short -q --cov=. --cov-report=term-missing
```

**CRITICAL (per D-14, pitfall 5 from research):** The `working-directory: backend` is required on the pytest step because `pytest.ini` is in `backend/` and `testpaths = tests` is relative to it. The `--cov=.` (not `--cov=backend`) is correct because working-directory is already `backend/`.

**Step 3 — Update deploy job `needs:` field (per D-13):**
Change the `deploy` job's `needs:` from:
```yaml
    needs: [security-quality-gate]
```
to:
```yaml
    needs: [security-quality-gate, unit-tests]
```

This ensures a test failure blocks deployment.

**Per D-17:** No `--cov-fail-under` threshold — report only. The coverage percentage will be visible in CI logs as a baseline.
