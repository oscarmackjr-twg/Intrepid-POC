**2a. GET /api/re/kpis (API-01)**

Single `.one()` aggregation query per D-07 using `func.sum` / UPB-weighted formulas:
- `total_upb = func.sum(RELoan.upb)`
- `active_loan_count = func.count(RELoan.id)`
- `wac = func.sum(RELoan.interest_rate * RELoan.upb) / func.nullif(func.sum(RELoan.upb), 0)` (UPB-weighted average coupon)
- `wam = func.sum(RELoan.wam_months * RELoan.upb) / func.nullif(func.sum(RELoan.upb), 0)` (cast wam_months to Numeric before multiply)
- `wa_ltv = func.sum(RELoan.ltv * RELoan.upb) / func.nullif(func.sum(RELoan.upb), 0)`
- `wa_dscr = func.sum(RELoan.dscr * RELoan.upb) / func.nullif(func.sum(RELoan.upb), 0)`
- `delinquent_30_upb = func.sum(case((RELoan.days_past_due >= 30, RELoan.upb), else_=0))`
- `delinquent_60_upb = func.sum(case((RELoan.days_past_due >= 60, RELoan.upb), else_=0))`
- `delinquent_90_upb = func.sum(case((RELoan.days_past_due >= 90, RELoan.upb), else_=0))`
- `portfolio_yield` = same as WAC (proxy metric for POC per RESEARCH.md A5)

Handle zero-row case: if `result.active_loan_count == 0` or `result.total_upb is None`, return all-zero/None KPIResponse.

**2b. GET /api/re/concentration (API-02)**

Multiple grouped queries against `RELoan`:
1. Property type breakdown: `GROUP BY property_type`, `func.count(id)`, `func.sum(upb)`. Compute `pct_of_total` as each group's UPB / total_upb. Total_upb comes from a separate `func.sum(upb).scalar()` with same filters.
2. State concentration: same pattern, `GROUP BY state`, ordered by UPB desc.
3. MSA concentration: same pattern, `GROUP BY msa`, ordered by UPB desc.
4. Top-10 exposures: `db.query(RELoan).filter(*filters).order_by(RELoan.upb.desc()).limit(10).all()` — return `TopExposure` for each.
5. Concentration limits: compute pct for top borrower (max single `borrower_name` UPB / total), top state, top property_type. Compare against hardcoded POC policy limits: `# TODO: POLICY-CONFIG — move to DB settings in production` — state: 25%, property_type: 40%, borrower: 10%.

**2c. GET /api/re/distributions (API-03)**

Three histogram datasets using SQL CASE-based bucket aggregation:
1. LTV histogram with CREDIT-01 color bands:
   - `<65%` (bucket="<65%", color="green"), `65-75%` (color="yellow"), `>75%` (color="red")

2. DSCR histogram with CREDIT-02 bands:

Each bucket query: `db.query(bucket_label, func.count(RELoan.id), func.sum(RELoan.upb)).filter(*filters).group_by(bucket_label).all()`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/re/* | Untrusted JWT and query params cross into server-side data access |
| FilterParams -> SQL query | User-supplied filter values injected into SQLAlchemy query |
| JWT claims -> sales_team_id scope | Server derives scope from JWT, not from client params |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Elevation of privilege | build_re_filters() | mitigate | sales_team_id injected server-side from user.sales_team_id (JWT); never accepted as a query param. build_re_filters() prepends scope filter before any client filter. |
| T-18-02 | Tampering | FilterParams.borrower | mitigate | SQLAlchemy `.ilike()` uses parameterized bind variable — no raw string interpolation. All other filter fields use exact-match `==` with typed params. |
| T-18-03 | Information disclosure | /api/re/kpis | mitigate | Aggregation queries apply scope filter — sales_team users cannot see portfolio-wide KPIs. Error responses do not leak SQL or internal state. |
| T-18-04 | Spoofing | All endpoints | mitigate | Every endpoint requires `Depends(require_sales_team_access())` which validates JWT via `get_current_user`. No unauthenticated access. |
| T-18-05 | Denial of service | FilterParams with extreme ranges | accept | Rate limiting already wired via slowapi in main.py. Aggregation queries are bounded by the seeded dataset size (~1000 rows). Acceptable risk for POC. |
| T-18-06 | Elevation of privilege | Missing auth on new router | mitigate | Every endpoint function signature includes `current_user: User = Depends(require_sales_team_access())`. Code review and test coverage confirm no endpoint is unprotected. |
</threat_model>
