**1a. GET /api/re/loans (API-05)**

Paginated, filterable, sortable loan list per D-05/D-06:
- Additional query params (NOT in FilterParams -- separate `Query` params): `page: int = Query(1, ge=1)`, `page_size: int = Query(50, ge=1, le=200)`, `sort_by: Optional[str] = Query(None)`, `sort_dir: str = Query("asc")`
- Sort whitelist: `ALLOWED_SORT_FIELDS = {"upb", "ltv", "dscr", "interest_rate", "maturity_date", "origination_date", "risk_rating"}`. If `sort_by` is provided and not in whitelist, raise `HTTPException(400, "Invalid sort field")`.
- Build base query: `db.query(RELoan).filter(*build_re_filters(db, filters, current_user))`
- Get total BEFORE pagination: `total = base_query.with_entities(func.count(RELoan.id)).scalar()` (Pitfall 2 from RESEARCH.md -- count before offset/limit)
- Apply sort: `order_col = getattr(RELoan, sort_by, RELoan.id)`, apply `.asc()` or `.desc()` based on `sort_dir`
- Apply pagination: `offset = (page - 1) * page_size`, then `.offset(offset).limit(page_size).all()`
- Return `LoanListResponse(total=total, page=page, page_size=page_size, items=items)`

**1b. GET /api/re/loans/{loan_id} (API-06)**

Single loan detail with payment history:
- Query: `db.query(RELoan).filter(RELoan.id == loan_id, *build_re_filters(db, filters, current_user)).first()`
- If not found (or outside scope for sales_team user): return `HTTPException(404, "Loan not found")` -- per RESEARCH.md API-06 note, return 404 not 403 to avoid disclosing loan existence.
- Payment history summary: aggregate linked cashflows:
  ```python
  cashflow_summary = db.query(
      func.sum(RELoanCashflow.scheduled_principal),
      func.sum(RELoanCashflow.actual_principal),
      func.sum(RELoanCashflow.scheduled_interest),
      func.sum(RELoanCashflow.actual_interest),
      func.count(RELoanCashflow.id),
  ).filter(RELoanCashflow.loan_id == loan_id).one()
  ```
- Build `LoanDetailResponse` with all fields from the loan plus `PaymentHistorySummary`.

**1c. GET /api/re/cashflow-performance (API-07)**

Monthly P&I actual vs projected, NOI trend, gross/net yield, CPR:
- Join RELoanCashflow to RELoan to apply filters: `db.query(...).join(RELoan, RELoanCashflow.loan_id == RELoan.id).filter(*build_re_filters(db, filters, current_user))`
- Group by `RELoanCashflow.period_date`, aggregate:
  - `func.sum(RELoanCashflow.scheduled_principal)`
  - `func.sum(RELoanCashflow.actual_principal)`
  - `func.sum(RELoanCashflow.scheduled_interest)`
  - `func.sum(RELoanCashflow.actual_interest)`
  - `func.sum(RELoanCashflow.noi)`
- Order by `period_date`.
- Post-process in Python for each period:
  - `gross_yield`: `actual_interest / total_upb * 12` (annualized) -- get total_upb from a separate filtered query on RELoan
  - `cpr`: `SMM = (actual_principal - scheduled_principal) / total_upb` then `CPR = 1 - (1 - SMM)^12`. If SMM <= 0, CPR = 0.
- `net_loss_rate`: `(total_scheduled - total_actual) / total_upb` for the whole period set. If negative (over-collection), clamp to 0.
- Return `CashflowPerformanceResponse`.

Pitfall guard (Pitfall 6): the group_by period_date prevents Cartesian product explosion.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/re/loans | Untrusted page/sort params + JWT cross into server-side query |
| client -> /api/re/loans/{id} | Untrusted loan ID -- must not disclose existence of out-of-scope loans |
| FilterParams -> cashflow join | Client filters applied across RELoan->RELoanCashflow join |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Elevation of privilege | /api/re/loans, /api/re/loans/{id} | mitigate | build_re_filters() prepends sales_team_id scope. Loan detail returns 404 (not 403) for out-of-scope loans -- prevents enumeration. |
| T-18-02 | Information disclosure | /api/re/loans/{id} | mitigate | Out-of-scope loan IDs return 404 identical to non-existent IDs. No error message difference between "doesn't exist" and "not your scope." |
| T-18-03 | Tampering | sort_by query param | mitigate | Whitelist of allowed sort fields: {"upb", "ltv", "dscr", "interest_rate", "maturity_date", "origination_date", "risk_rating"}. Reject unknown values with 400. Prevents arbitrary column access. |
| T-18-04 | Tampering | page_size param | mitigate | Constrained via `Query(50, ge=1, le=200)` -- prevents memory exhaustion from requesting millions of rows. |
| T-18-05 | Information disclosure | /api/re/cashflow-performance | mitigate | Cashflow join applies same build_re_filters() scope -- sales_team users cannot see other teams' cashflow data. |
| T-18-06 | Denial of service | /api/re/cashflow-performance join | accept | Join is bounded by seeded dataset (~6000 cashflows). Group-by period_date prevents row explosion. Acceptable for POC. |
| T-18-07 | Spoofing | /api/re/market-context | accept | Endpoint returns hardcoded stubs -- no sensitive data. Auth still required to prevent unauthenticated enumeration. |
</threat_model>
