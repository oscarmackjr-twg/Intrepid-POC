class RELoan(Base):
    __tablename__ = "re_loans"

    borrower_name = Column(String(255))
    sales_team_id = Column(Integer, ForeignKey("sales_teams.id"), nullable=True)
    as_of_date = Column(Date, nullable=False, index=True)
    upb = Column(Numeric(18, 6))
    original_balance = Column(Numeric(18, 6))
    interest_rate = Column(Numeric(10, 6))
    wam_months = Column(Integer)
    ltv = Column(Numeric(10, 6))
    dscr = Column(Numeric(10, 6))
    property_type = Column(String(50), index=True)
    state = Column(String(2), index=True)
    msa = Column(String(100))
    risk_rating = Column(String(10))
    prior_risk_rating = Column(String(10))
    rate_type = Column(String(20))
    origination_date = Column(Date)
    maturity_date = Column(Date)

**Loan generation logic:**

For each of the 500 T0 loans:
1. `loan_number`: `f"RE-{i+1:05d}"` (RE-00001 through RE-00500)
2. `borrower_name`: `fake.company()`
3. `sales_team_id`: `None` (no sales teams seeded yet; Phase 27 handles this)
4. `as_of_date`: `T0_DATE` (2025-09-30)
5. `upb`: `rng.uniform(500_000, 50_000_000)` -- wide range for CRE
6. `original_balance`: `upb * rng.uniform(1.0, 1.15)` -- original >= current UPB
7. `interest_rate`: `rng.normal(5.5, 1.2)` clipped [2.5, 9.0]
8. `wam_months`: `rng.integers(12, 360)`
9. `ltv`: `rng.normal(0.67, 0.08)` clipped [0.40, 0.95] per CONTEXT.md
10. `dscr`: inversely correlated with LTV: `1.35 - 0.8*(ltv - 0.67) + rng.normal(0, 0.20)` clipped [0.70, 2.80] per CONTEXT.md
11. `property_type`: weighted random from PROPERTY_TYPES
12. `state`: weighted random from STATE_MSA_MAP keys using STATE_WEIGHTS
13. `msa`: random choice from STATE_MSA_MAP[state]
14. `risk_rating`: weighted random from RISK_RATINGS using RISK_WEIGHTS
15. `prior_risk_rating`: same as `risk_rating` for T0 (T0 is the base snapshot)
16. `rate_type`: weighted random from RATE_TYPES
17. `origination_date`: random date between 2018-01-01 and 2025-06-30
18. `maturity_date`: `origination_date + timedelta(days=rng.integers(365*3, 365*10))`
19. `days_past_due`: 0 for current, 30/60/90 based on DELINQ_STATUS weights
20. `delinquency_status`: matches days_past_due bucket
21. `pipeline_stage`: weighted random from PIPELINE_STAGES
22. `vintage_year`: `origination_date.year`

**T1 snapshot generation (~500 more rows):**

For each T0 loan, create a T1 copy with:
- Same `loan_number`, `borrower_name`, etc.
- `as_of_date = T1_DATE` (2025-12-31)
- `prior_risk_rating` = T0's `risk_rating`
- `risk_rating`:
  - ~8% chance: downgrade one notch (e.g., BBB -> BB). Use RISK_RATINGS index + 1, capped at CCC.
  - ~5% chance: upgrade one notch (e.g., BBB -> A). Use RISK_RATINGS index - 1, floored at AAA.
  - ~87% chance: unchanged
- Slightly adjust `upb` (multiply by `rng.uniform(0.95, 1.02)` -- amortization or draw)
- Slightly adjust `days_past_due` -- small chance of status change

**Cashflow generation (12 records per T0 loan only):**

For each T0 loan, generate 12 monthly records from Oct 2024 to Sep 2025:
- `period_date`: 1st of each month (2024-10-01, 2024-11-01, ..., 2025-09-01)
- `scheduled_principal`: `loan.upb / 360 * 1` (simplified monthly amortization)
- `actual_principal`: `scheduled_principal * rng.uniform(0.90, 1.05)` (slight variance)
- `scheduled_interest`: `loan.upb * (loan.interest_rate / 100 / 12)` (monthly interest)
- `actual_interest`: `scheduled_interest * rng.uniform(0.95, 1.02)`
- `noi`: `rng.uniform(5000, 200000)` scaled proportionally to loan.upb (e.g., `loan.upb * rng.uniform(0.04, 0.08) / 12`)

All cashflow amounts must use `to_dec()` conversion.

**Seed function:**

```python
def seed_re_loans() -> None:
    db: Session = SessionLocal()
    try:
        # Idempotent: truncate child before parent (FK constraint order)
        db.query(RELoanCashflow).delete()
        db.query(RELoan).delete()
        db.commit()

        t0_loans = []  # generate 500 T0 loans
        # ... generation loop ...
        db.add_all(t0_loans)
        db.flush()  # get auto-generated IDs (autoflush=False in SessionLocal)

        t1_loans = []  # generate T1 copies
        # ... generation loop ...
        db.add_all(t1_loans)

        cashflows = []  # 12 records per T0 loan
        # ... generation loop referencing t0_loan.id ...
        db.add_all(cashflows)
        db.commit()

        print(f"Seeded {len(t0_loans)} T0 loans, {len(t1_loans)} T1 loans, {len(cashflows)} cashflow records")
    finally:
        db.close()

if __name__ == "__main__":
    seed_re_loans()
```

**Important implementation notes:**
- Use `db.add_all()` not `db.bulk_save_objects()` -- add_all triggers relationship tracking needed for `loan.id` reference in cashflows
- Use `db.flush()` after adding T0 loans to get their `id` values before inserting cashflows
- T1 loans do NOT get cashflow records (per CONTEXT.md: "cashflows belong to the loan, not the snapshot")
- `sales_team_id` is `None` for all seeded loans (no sales teams seeded in this phase)
