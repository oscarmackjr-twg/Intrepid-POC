<task type="auto">
  <name>Task 2: Build, tag, and push new image to ECR :latest, then force ECS redeploy</name>
  <files></files>
  <action>
Run from repo root `C:\Users\omack\Intrepid\pythonFramework\intrepid-poc` in PowerShell.

1. Set variables:
   ```powershell
   $Region  = "us-east-1"
   $Profile = "AWSAdministratorAccess-014148916722"
   $EcrRepo = "014148916722.dkr.ecr.us-east-1.amazonaws.com/intrepid-poc-qa"
   $EcrHost = "014148916722.dkr.ecr.us-east-1.amazonaws.com"
   $Cluster = "intrepid-poc-qa"
   $Service = "intrepid-poc-qa"
   ```

2. ECR login:
   ```powershell
   aws ecr get-login-password --region $Region --profile $Profile | `
     docker login --username AWS --password-stdin $EcrHost
   ```
   Expect: `Login Succeeded`. If fails, STOP — create auth checkpoint.

3. Build image from repo root using `deploy/Dockerfile` (matches deploy-qa.ps1 pattern exactly).
   Tag with both `:latest` and the git short sha for traceability:
   ```powershell
   $Sha = (git rev-parse --short HEAD)
   docker build -f deploy/Dockerfile -t "${EcrRepo}:latest" -t "${EcrRepo}:${Sha}" .
   ```
   Expect: build succeeds, final image ID printed. If build fails, STOP and report the error —
   do not push or deploy. This is a no-code-changes task; a build failure is unexpected.

4. Push both tags:
   ```powershell
   docker push "${EcrRepo}:latest"
   docker push "${EcrRepo}:${Sha}"
   ```

5. Confirm the new digest in ECR differs from the old digest captured in Task 1:
   ```powershell
   aws ecr describe-images `
     --repository-name intrepid-poc-qa `
     --image-ids imageTag=latest `
     --region $Region --profile $Profile `
     --query "imageDetails[0].{digest:imageDigest,pushedAt:imagePushedAt,tags:imageTags}" `
     --output json
   ```
   Expect: digest differs from Task 1 capture; `tags` contains both `latest` and `$Sha`.

6. Force a new ECS deployment:
   ```powershell
   aws ecs update-service `
     --cluster $Cluster --service $Service `
     --force-new-deployment `
     --region $Region --profile $Profile `
     --query "service.deployments[0].{status:status,rolloutState:rolloutState,taskDef:taskDefinition}" `
     --output json
   ```

7. Wait for the service to stabilize (new tasks running, old tasks drained):
   ```powershell
   aws ecs wait services-stable `
     --cluster $Cluster --services $Service `
     --region $Region --profile $Profile
   ```
   This blocks up to ~10 min. If it times out, run `aws ecs describe-services` and inspect
   `deployments[]` + `events[0..5]` to diagnose; do NOT mark task done until stable.

8. Confirm running task is on the new image:
   ```powershell
   $taskArn = (aws ecs list-tasks --cluster $Cluster --service-name $Service `
     --desired-status RUNNING --region $Region --profile $Profile `
     --query "taskArns[0]" --output text)
   aws ecs describe-tasks --cluster $Cluster --tasks $taskArn `
     --region $Region --profile $Profile `
     --query "tasks[0].containers[0].{image:image,imageDigest:imageDigest,lastStatus:lastStatus}" `
     --output json
   ```
   Expect: `lastStatus=RUNNING`, `imageDigest` matches the new digest from step 5.
  </action>
  <verify>
    <automated>aws ecr describe-images shows new digest != old digest; aws ecs wait services-stable exits 0; aws ecs describe-tasks shows running task imageDigest matches new ECR digest</automated>
  </verify>
  <done>New image pushed to ECR as :latest and :$Sha with a new digest; ECS service rolled via force-new-deployment; services-stable returned; running task's imageDigest equals the new ECR digest.</done>
